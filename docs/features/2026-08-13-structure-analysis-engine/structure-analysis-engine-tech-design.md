층0 설계와 결정적으로 다른 점이 있다. **층0은 가정 위에서 설계했고 실데이터가 결함 9건을 드러냈다.** 그 교훈으로 층1은 **설계 전에 탐침을 먼저 돌렸다** (`scripts/boundary_experiment.py`, 커밋 `8ee5c56`).

## 1. 아키텍처 개요

### 파이프라인 — 게이트 두 개가 앞을 막는다

```
층0 산출물 (엣지 목록 + evidence_weight 인자 + 품질지표)
   │
   ├─▶ [G1] 품질 게이트 ─── 해소율 → 재현율 미달 시 실행 거부 (AC-12)
   │
   ├─▶ [G2] 경계 게이트 ─── 경계 노드 비율 초과 시 층위·중심성 거부 (AC-14)
   │                        ※ 군집은 경계에 견디므로 통과시킨다
   ▼
[1] 렌즈 적용 ── include 관계타입만 남긴다 (겹1, 이진)
   ▼
[2] 가중치 주입 ── evidence_weight = 겹2 × 겹3 (층0 인자에서 파생)
   ▼
[3] 투영 두 벌
   ├─ UNDIRECTED ─▶ [4] 군집 (Leiden 모듈러리티 + CPM)
   └─ NATURAL ────▶ [5] 층위·중심성 (입출차수 · 깊이 · betweenness)
   ▼
[6] 지표표 ── 군집별 노드/내부엣지/외부엣지/의존도/평균깊이
   ▼
[7] 검증 ③④
   ├─ 차수보존 귀무모형 N회 → (실제, 평균, 표준편차, z)
   └─ 민감도 스윕 (해상도 + 겹2 계수) → 결론 유지/뒤집힘
   ▼
[8] 결론 판정 ── 채택 | 결론 없음 | 파라미터 의존적   ← 세 상태 동등
   ▼
[9] 근거 블록 직렬화 ── 층2의 렌더 입력 (이 층의 계약)
   ▼
[10] LLM 해석 ── 표만 보고 문장. 수치 밖 고유명사·숫자 금지 (AC-9)
```

**게이트가 앞에 있는 게 핵심이다.** 요구사항 결정 11이 *"일단 돌려보고 나중에 판단"* 을 금지하는데, 게이트를 뒤에 두면 이미 계산된 결과를 보고 나서 판단하게 되어 사후 합리화가 들어온다.

### 실행 형태 — 라이브러리 + 얇은 CLI

층1은 **화면 없는 배치 분석**이다. `analyze(edges, lens, config) -> Report` 순수 함수를 중심에 두고 CLI 는 그걸 부르는 껍데기로만 만든다. 층2가 나중에 같은 함수를 부른다.

## 2. 영향 받는 컴포넌트/파일

전부 신규. 층0 코드는 **읽기만 하고 수정하지 않는다** — 층0은 실데이터로 검증이 끝난 상태이므로 건드릴 이유가 없다.

```
src/dartweave/structure/           ← 신규 패키지
├─ lens.py            렌즈 프리셋 (include 목록만, 중간 가중치 상수 없음)
├─ weight.py          겹2×겹3 파생 → igraph edge weight 주입
├─ project.py         투영 두 벌 (UNDIRECTED / NATURAL) + 경계 판정
├─ cluster.py         Leiden(모듈러리티) + CPM 병행, 비교표
├─ topology.py        층위 — 입·출차수, 공급 깊이
├─ centrality.py      betweenness (경계 게이트 통과 시에만)
├─ metrics.py         군집별 지표표 (노드/내부/외부/의존도/깊이)
├─ nullmodel.py       차수보존 셔플 N회 → z 통계
├─ sensitivity.py     해상도 + 겹2 계수 스윕
├─ verdict.py         결론 판정 3상태 (동등한 반환값)
├─ evidence.py        근거 블록 직렬화 — 층2 계약
├─ interpret.py       LLM 해석 + 수치 밖 토큰 검사
└─ pipeline.py        analyze() — 위를 순서대로 엮는 순수 함수

scripts/analyze_structure.py       CLI 껍데기
tests/structure/                   모듈별 단위 + 골든
```

## 3. 데이터 모델

**DB 없음.** 입력은 층0의 엣지 목록(JSON), 출력은 근거 블록(JSON). 영속 저장은 층2에서 Neo4j 를 세울 때 결정한다.

### 입력 계약 (층0 → 층1)

```
edge  = (start_corp_code, end_corp_code, edge_type,
         evidence_inputs, as_of, fiscal_year)
quality = { resolution_rate, recall, precision_samples, ... }
```

`evidence_inputs` 는 층0 AC-8 의 인자 묶음이다 — **`evidence_weight` 값 자체가 아니라 인자**를 받는다. 층0 D5 가 값을 저장하지 않기로 한 이유(실측 정확도 표가 갱신되면 전체가 바뀜)가 여기서도 그대로 적용된다.

### 출력 계약 (층1 → 층2) — `evidence.py`

요구사항 §5 의 근거 블록을 그대로 구조체화한다. **이 스키마가 층2의 렌더 입력이자 층1의 완료 판정**이다.

```
EvidenceBlock
├─ lens         { name, include_types }
├─ algorithm    { name, objective, resolution, n_clusters }
├─ clusters[]   { id, nodes, internal_edges, external_edges,
                  dependency_ratio, mean_supply_depth }
├─ verification
│   ├─ edges      { recall, precision, precision_n, resolution_rate }
│   ├─ rules      { violations, isolated, duplicate_ratio }
│   ├─ structure  { modularity, null_mean, null_sd, z, runs,
│                   cpm_clusters, cpm_delta }
│   └─ stability  { resolution_sweep[], coefficient_sweep[], holds }
├─ scope        { companies, disclosures, fiscal_year, boundary_ratio }
└─ verdict      ACCEPTED | NO_CONCLUSION | PARAMETER_DEPENDENT
```

> ⚠️ `scope.boundary_ratio` 가 필수다. AC-13(범위 명시)과 AC-14(경계 게이트)가 한 필드에서 만난다.

## 5. 핵심 결정 + 대안 비교

### D1 — 그래프 엔진: **igraph 단독** (Neo4j+GDS 유예)

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **igraph 단독** | 탐침에서 **이미 작동 검증**. CPM 지원. 컨테이너 불필요 | 영속성 없음 · 질의어 없음 | ✅ **채택** |
| Neo4j+GDS+igraph | Cypher 임의 질의 · 영속성 | **GDS 미검증**(`gds.version()` 미실행) · CPM 없어 igraph 여전히 필요 → 이중 관리 | ✗ (층2로 유예) |
| networkx 단독 | 순수 파이썬 | Leiden 미내장 · 대규모에서 느림 | ✗ |

**근거**: GDS 에 CPM 이 없고(요구사항 결정 7) 차수보존 셔플도 없다(AC-5). 즉 **Neo4j 를 써도 igraph 를 못 뺀다.** 층1은 배치 계산이라 Cypher 임의 질의가 급하지 않다. Neo4j 의 값어치는 **층2에서 사용자가 노드를 클릭할 때** 나온다 — 그때 붙인다.

> 층0 설계(D1)에서 Neo4j+GDS 를 택했던 것과 어긋나 보이지만, 층0은 **저장·적재** 관점이었고 층1은 **계산** 관점이다. 저장은 여전히 Neo4j 가 맞다. 다만 **층1이 그걸 기다릴 이유가 없다.**

### D2 — 경계 게이트를 **층위·중심성에만** 건다

| 대안 | 판정 |
|---|---|
| **군집은 통과, 층위·중심성만 차단** | ✅ 실측: 경계 닫아도 효과크기 **+0.1211→+0.1305 유지** vs 출차수 1위 **한화→태영건설 역전** |
| 전부 차단 | ✗ 군집은 경계에 견디는데 막을 이유가 없다 |
| 전부 통과 | ✗ 층위 지표가 틀린 결론을 낸다 |

**군집 구조는 경계에 견디고 방향 지표는 못 견딘다** — 이게 실측이 준 비대칭이고, 게이트를 비대칭으로 설계하는 근거다.

### D3 — 파이프라인은 **순수 함수**, CLI 는 껍데기

| 대안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| **`analyze()` 순수 함수 + 얇은 CLI** | 테스트 쉬움 · 층2가 같은 함수 재사용 | — | ✅ |
| CLI 스크립트에 로직 직접 | 빠른 작성 | 층2에서 통째로 재작성 | ✗ |

층0에서 `run_stage.py` 가 `init_schema` 를 무조건 호출해 **DB 없이는 아무 단계도 못 도는** 갭이 나왔다(CH-015). 같은 실수를 반복하지 않으려면 **로직이 실행 환경에 안 묶여야 한다.**

### D4 — 모듈러리티는 **귀무모형 대조로만** 판정

절대 기준 금지. 실측이 이유를 보여준다 — 0.8535 는 "매우 우수"처럼 보이지만 **차수보존 귀무모형이 이미 0.7230**이다. 절대 기준을 썼으면 판단이 통째로 틀렸다. 실제 신호는 **효과크기 +0.1305**.

대안(절대 임계 0.3)은 문헌 근거가 없고 네트워크 크기·밀도 의존적이라 채택하지 않는다.

### D5 — CPM 병행은 **필수**, 선택 아님

실측: CPM(0.005) **52군집** vs 모듈러리티 **38군집** — 모듈러리티가 **14개를 놓친다**. Fortunato–Barthélemy 해상도 한계가 이 데이터에서 실제로 작동 중이다.

대안(모듈러리티만)은 작은 군집을 구조적으로 못 보므로, 요구사항의 하이라이트(소수 의존 구간)를 놓칠 수 있다.

### D6 — 민감도 스윕은 **반려 권한**을 갖는다

실측: 해상도 0.5→2.0 에서 최대 군집 **126→69**. *"가장 큰 군집이 N개사"* 류 결론은 이 구간을 못 버틴다.

따라서 `sensitivity.py` 는 보고용 부록이 아니라 **`verdict.py` 의 입력**이다. 스윕에서 뒤집히면 `PARAMETER_DEPENDENT` 로 반려된다.

### D7 — LLM 해석은 **표 → 문장 변환기**

숫자를 만들지 않는다. 검증 방식은 **출력 토큰이 입력 수치·고유명사 집합에 포함되는지** 기계 검사(AC-9). 대안(사후 사실검증)은 환각을 잡는 게 아니라 **발생 못 하게 하는 것**보다 약하다.

## 6. 위험 / 사이드이펙트

| 위험 | 카테고리 | 대응 |
|---|---|---|
| **경계 게이트 임계값이 임의값** | side-effect | 설정으로 노출 + 출력 명시(AC-14). 실측 기준선(경계 비율 48%→0%) 을 문서에 남김 |
| **귀무모형 반복수가 z 를 좌우** | side-effect | 반복수 설정화 + 출력 명시(AC-5). 실측 20회에서 sd 0.0007 로 안정 |
| 겹2 계수 스윕이 조합 폭발 | side-effect | 축별 독립 스윕(전수 조합 X). 상호작용은 범위 밖으로 명시 |
| **`결론 없음` 이 실패로 취급됨** | breaking | 3상태를 같은 반환 타입으로. 예외·에러 경로 금지(AC-10) |
| 렌즈에 중간 가중치가 슬며시 도입 | breaking | `lens.py` 는 `include` 목록만 보유. 상수 필드 자체를 두지 않음(AC-1) |
| 군집에 의미 라벨이 붙음 | breaking | 라벨링 함수를 만들지 않음. 서술은 군집번호+수치만(AC-4) |
| igraph 버전에 따른 Leiden 시드 차이 | side-effect | `n_iterations`·시드 고정 + 골든 테스트로 회귀 감지 |
| 층0 품질 지표가 아직 미완 | **blocking** | 재현율·정밀도는 슬라이스2 소관. G1 게이트는 **해소율만으로 먼저 동작**하고 나머지는 값이 오면 활성 |
| 해소율 지표가 자연인/법인 미분리 | **breaking** | 실측 29.7% 는 개인 주주 때문이며 정상. **G1 이 이 값을 그대로 임계로 쓰면 정상을 불합격 처리한다** → 분리 집계가 G1 활성의 선행조건 |

> ⚠️ `race` 카테고리 없음 — 단일 프로세스 배치. 스윕을 병렬화하면 재평가 필요.

## 7. 테스트 전략

**핵심 원칙: 구조 분석은 "정답"이 없다. 따라서 성질(property)을 테스트한다.**

| 층위 | 대상 | 방법 |
|---|---|---|
| **성질** | 귀무모형이 실제보다 낮다 | 합성 그래프(계획된 군집 구조)에서 z > 0 |
| **성질** | 무구조 그래프는 z 가 낮다 | Erdős–Rényi 에서 z 가 임계 미만 → `결론 없음` |
| **성질** | 차수보존 셔플이 차수를 보존한다 | 셔플 전후 차수 수열 동일 |
| **단위** | 렌즈가 include 외 타입을 제거 | 관계타입 필터 결과 |
| **단위** | 경계 게이트가 층위를 차단 | 경계 비율 초과 시 층위 산출이 없음 |
| **단위** | 3상태가 동등 반환 | `결론 없음` 이 예외를 던지지 않음 |
| **단위** | LLM 출력 토큰 검사 | 입력에 없는 고유명사 주입 시 실패 판정 |
| **골든** | 실측 그래프 재현 | `data/graph_closed.json` 로 모듈러리티·군집수 고정 (igraph 버전 회귀 감지) |
| **통합** | `analyze()` 端到端 | 소량 합성 그래프 → 근거 블록 스키마 완전성 |

**LLM 해석 테스트는 모델 호출 없이 한다** — `interpret.py` 를 (프롬프트 생성 + 출력 검사) 두 부분으로 쪼개고, 검사 함수만 단위 테스트한다. 모델 응답 품질은 테스트 대상이 아니다.
