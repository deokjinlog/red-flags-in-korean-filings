# red-flags-in-korean-filings

전자공시로 **"이 회사 사도 되나"** 에 근거를 대려던 기록이다.
상장사 8,974개사 · 지분 관계 54,569건 · 부실 라벨 810건 · 기준시점 4개.

점수를 내지 않는다. **무엇이 걸렸고, 그 검사가 검정을 통과했는지**만 낸다.

**▶ [실행 결과 화면](https://deokjinlog.github.io/red-flags-in-korean-filings/)**

---

## 결론

출발점은 "지분 구조로 부실을 예고한다" 였고, **그건 안 됐다.**

| | 검사 | 채택 |
|---|---|---|
| 지분 구조 | 7종 | **0종** |
| 재무 | 8종 | **5종** |

안 된다는 걸 **재무 대조군을 같은 잣대에 넣어서** 보였기 때문에, "우리 방법이
틀렸다" 가 아니라 **"구조에 그 신호가 없다"** 로 말할 수 있다. 잣대는 멀쩡했다 —
같은 통제·같은 시점 분리·같은 채택 규칙을 재무 신호는 통과한다.

채택된 다섯은 이렇다. 규모·업종 통제 7설정 × 기준시점 4개 = **28조합 전부**에서
유의하고, 관측 창을 365·730·1095일로 흔들어도 판정이 **한 번도 뒤집히지 않는다.**

```
                T=2021        T=2022        T=2023        T=2024
  결손금          ×6.78 .0001   ×4.16 .0001   ×2.69 .0001   ×4.53 .0001
  이자보상배율<1   ×3.44 .0002   ×3.32 .0001   ×1.82 .0044   ×3.70 .0001
  당기순손실       ×3.41 .0002   ×2.27 .0016   ×2.43 .0002   ×4.03 .0001
  영업손실        ×2.44 .0010   ×2.96 .0004   ×1.96 .0030   ×3.13 .0001
  영업현금흐름 음수  ×2.01 .0082   ×2.16 .0011   ×1.96 .0046   ×3.78 .0001
```

**그런데 이걸 "이 회사는 망한다" 로 읽으면 안 된다.** 기저율이 4.1% 라 ×2.4 는 10% 다.
가장 정밀한 조합조차 **걸린 것의 89%가 2년 안에 아무 일도 없었다.**
그래서 이 도구는 매수·매도를 말하지 않는다.

## 두 가지로 쓴다

**① 질문 → 그래프 검색**

```bash
uv run python scripts/ask.py "삼부토건 사도 되나?"
```
```

[결손금]            2023년 누적 결손 2,043억
[영업손실]          2023년 영업손실 782억
[당기순손실]         2023년 순손실 1,110억
[영업현금흐름 음수]    2023년 유출 1,071억
[이자보상배율 1 미만]  영업손실이라 이자 갚을 재원이 없다 (이자 93억)

── 걸렸지만 검정 미통과 (참고) ──
[대기업집단과의 거리] 고립 — 규모·업종을 맞추면 차이가 사라진다

모델에 넘길 것   근거 2,121자 · 허용 토큰 121개
```

삼부토건은 실제로 2025-04 회생절차개시신청으로 관리종목이 됐다. 2023년 6월에 서서
저 다섯을 보고 "여기 걸렸다" 고 말할 수 있었다. **동시에 같은 신호에 걸린 나머지
90%는 아무 일도 없었다.**

답을 **검정 통과 / 미통과로 갈라서** 낸다. 그 순서가 곧 "무엇을 믿고 말할 수 있는가" 다.
모델은 저 토큰 안에서만 말할 수 있고, 벗어나면 `HallucinationDetected` 로 중단된다.

구조 검색이 하는 일은 따로 있다 — **질문에 없는 것을 가져온다.** "태영건설이 흔들리면
어디가 위험해?" 에 `건설공제조합` 이 나오는데, 그 이름은 질문 어디에도 없다. 벡터
유사도로는 안 나오고 한 홉 건너야 나온다. 다만 **검색이 잘 가져오는 것과 그게 부실을
예고하는 것은 다른 문제**였고, 이 저장소의 결론이 그 차이다.

| 검사 | 부실과 연관되는가 |
|---|---|
| 결손금 (재무) | **채택** — 28조합 전부 유의 · **네 시점 전부 Bonferroni 통과 (유일)** |
| 이자보상배율 1 미만 (재무) | **채택** — 28조합 전부 유의 · Bonferroni 4개 중 3개 |
| 당기순손실 (재무) | **채택** — 28조합 전부 유의 · Bonferroni 4개 중 3개 |
| 영업손실 (재무) | **채택** — 28조합 전부 유의 · Bonferroni 4개 중 3개 |
| 영업현금흐름 음수 (재무) | **채택(약)** — 28조합 전부 유의 · Bonferroni 4개 중 2개 |
| 부채비율 200% 초과 (재무) | 아직 모름 — 판정 난 6칸 전부 채택인데 4시점 중 3시점만 판정 |
| 자본잠식 (재무) | 아직 모름 — **부실률은 가장 높은데**(9.4~20.4%) 해당 91~108사뿐 |
| 매출 감소 (재무) | **반려** — 창에 따라 채택과 탈락이 갈린다 |
| 대기업집단과의 거리 | **반려** — 4시점 중 **최근 둘에서만** 나타남 (×0.45→×1.77) |

| 계열 경계 초과 | 미검정 — 공정위 집단명이 DART 에 없다 |

**걸렸다는 것과 위험하다는 것은 다른 말이다.** 도구가 그 둘을 같이 낸다.

## 어떻게 검정하는가 — 여섯 개의 규율

이 저장소가 여덟 번 결과를 뒤집은 건 규율을 하나씩 추가하면서다.
전부 **실패에서 나왔다.**

**① 시점 분리.** 특징은 T 이전, 라벨은 T 이후 730일. 엣지는 T 에 공시된 것만,
자산은 T 이전 사업연도 값. `db/asof.py` 가 `as_of` 와 `rcept_dt` 를 **둘 다** 건다 —
하나만 걸면 나중에 정정된 값이 딸려 온다.

**② 회사 단위.** 같은 회사를 여러 기준시점에 걸쳐 합치지 않는다. 순환출자 검정에서
×4.18 p=0.0005 가 **같은 회사를 네 번 세서** 만들어진 적이 있다.

**③ 커버리지.** 그래프에 아예 없는 회사가 오히려 문제가 적다(2.2% vs 6.6%). 구조
검정은 그래프 안에서만 비교한다. 반대로 **재무 검정에는 그래프 소속을 요구하지 않는다** —
요구했다가 DART 타법인출자 API 의 연도별 수록 편차에 표본이 좌우된 적이 있다.

**④ 교란 통제 + 최보수 채택.** 자산총계 × 표준산업분류 교차 층화, 층 안에서만 순열
(`signal/test.py` 의 `stratified_permutation_test`). 층을 쪼개면 검정력이 죽으니 층은
보존한 채 합친다. 그리고 **설정을 8개 흔들어 가장 보수적인 답을 결론으로 삼는다** —
유의해지는 설정을 골라 쓰면 그건 파라미터 고르기다.

**⑤ 다중검정 보정.** 판정이 난 검정 35개를 한 가족으로 묶어 Bonferroni · BH
(`signal/multiplicity.py`). 통제 설정 8개는 서로 다른 가설이 아니라 같은 가설의
민감도 스윕이라 하나로 센다.

**⑥ 관측 창 스윕.** 730 도 우리가 고른 값이라 365·1095 로 흔든다. 창이 수집 끝을
넘으면 `CensoredWindowError` 로 막는다 — 절단은 **조용히** 부실률을 낮춘다.

라벨 자체도 지킨다. `signal/labels.py` 의 `is_distress()` 하나가 무엇을 부실로 셀지
정한다. 해산(PFV·SPC 만기 종료)과 상장폐지 중 합병·스팩청산·이전상장을 세면
**"합병당한 회사" 를 부실로 예측하는 셈**이 되어 라벨이 통째로 오염된다.

## 여덟 번 무너진 기록

그럴듯한 결과가 먼저 나왔고, 한 번 더 확인할 때마다 무너졌다.

| | 이렇게 보였다 | 실제로는 |
|---|---|---|
| 1 | 층1 모듈러리티 0.8535 = 매우 우수 | 귀무모형이 이미 0.7223 · 해상도 1.85배 흔들림 → **반려** |
| 2 | 공동의존점에 가까우면 위험 | **반대 방향** — 먼 쪽이 2배 (p=0.0007) |
| 3 | 순환출자 ×4.18 · p=0.0005 | 같은 회사를 네 번 셈 → 회사 단위로는 표본 미달 |
| 4 | 연결 수 많으면 부실 ×1.90 | **탐지 편향** — 공시 많이 내면 많이 걸린다. 층화하니 붕괴 |
| 5 | 고립이 위험 ×3.61 (감사의견) | 규모·업종 통제하니 ×1.29 로 사라짐 |
| 6 | 규모 통제 후 ×1.69 는 남는다 | 업종까지 통제하니 그것도 사라짐 |
| 7 | 부실 이벤트로 보면 ×1.70 | 기준시점 4개 중 **둘은 방향이 반대** |
| 8 | 당기순손실은 시점에 따라 갈린다 | **내 실수** — 표본을 그래프로 좁혀놔서 얇았다. 풀자 4/4 재현 |

몇 개는 더 짚을 값이 있다.

**5·6번 — 고립 신호.** 통제를 촘촘히 할수록 ×1.84 → ×1.29 로 계속 줄고 유의성이
사라졌다. 유의해지는 설정을 골라 쓰면 그건 파라미터 고르기라, 층1 모듈러리티를
반려한 것과 **같은 이유로** 채택하지 않았다.

**7번 — 그래도 죽지는 않았다.** 4시점 배율이 ×0.45 → ×0.83 → ×1.46 → ×1.77 로
단조 증가한다. 같은 순서로 그래프 엣지도 4,794 → 15,445 로 느는데, 가장 잘 채워진
T=2024 분류를 모든 시점에 적용해봐도(미래 훔쳐보기라 **진단이지 주장이 아니다**)
×0.81 → ×1.25 → ×1.96 → ×2.34 로 추세가 남는다. 건설·부동산을 빼면 오히려
커진다(×2.34 → ×3.37). 그러니 "구조에 신호가 없다" 보다 **"최근 두 시점에서만
나타나고 왜인지는 이 데이터로 못 가른다"** 가 정확하다.

**절단 — 아홉 번째가 될 뻔했다.** 배율이 시점마다 줄어드는 걸 "시점에 따른 차이" 로
읽을 뻔했는데, T=2023 의 730일 창이 **546일에서 잘려 있었다.** 미래를 훔쳐보는 것의
반대쪽 실수이고, 빠뜨려도 결과가 그럴듯해서 티가 안 난다. 사건을 2026-08 까지
수집해 창을 채우고, 코드가 이걸 막게 만들었다.

**더 재면 대가를 치른다.** 신호를 둘 더 검정하면서 다중검정 가족이 26 → 35 로 커졌고
Bonferroni 임계가 0.00192 → 0.00143 으로 조여졌다. **기존 신호들의 등급이 같이
내려갔다** — 당기순손실은 4/4 에서 3/4 가 됐다. 버그가 아니라 보정의 정의다.

## 유의한 것과 쓸 만한 것은 다른 말이다

```
T=2024-06-30 · 2,246사 · 이후 2년 부실 91사 (기저율 4.1%)

  결손금         걸림 595사(26%) · 정밀도 9.6% · 재현율 63% — 90%는 무사
  영업현금흐름 음수 걸림 726사(32%) · 정밀도 8.4% · 재현율 67%
  당기순손실      걸림 811사(36%) · 정밀도 7.9% · 재현율 70%
  영업손실       걸림 746사(33%) · 정밀도 7.8% · 재현율 64%
  셋 중 하나     걸림 1,029사(46%) · 정밀도 6.9% · 재현율 78%
  셋 다          걸림 398사(18%) · 정밀도 11.3% · 재현율 49%
```

**넓게 걸수록 많이 잡지만 정밀도는 안 오른다.** 셋 중 하나로 넓히면 상장사의 46%가
걸리고 재현율이 78%까지 오르는데 정밀도는 6.9% 로 오히려 떨어진다. 셋 다로 좁히면
정밀도가 11.3%로 오르지만 재현율이 49%로 반토막 난다.
**어느 조합도 "이 회사는 위험하다" 를 말할 만큼 정밀하지 않다.**

⚠️ 여기 배율은 검정 쪽과 **분모가 다르다.** 검정은 신호군 대 **비신호군**(통제 후)이고
이건 신호군 대 **전체**(무통제)다. 답하는 질문이 다르다 — 검정은 "우연인가",
이쪽은 "그래서 무엇을 할 수 있는가".

`uv run python scripts/signal_usefulness.py`

## 막다른 길 — 시도했는데 안 된 것들

되는 것만 적으면 다음 사람이 같은 벽에 다시 부딪힌다.

**관리종목 지정 (KRX KIND)** — 상장폐지보다 이른 신호라 라벨로 더 낫다. 그런데
KIND 가 주는 건 **현재 지정된 종목**이지 과거 이력이 아니다(2019~2021년 0건,
2026년 115건). 과거 시점 라벨로 쓰면 **생존편향**이 생긴다.

**자본잠식** — 데이터는 있는데 표본이 구조적으로 부족하다. 완전자본잠식은 18~21사,
부분까지 합쳐도 91~108사다. 그런데 부실률이 9.4~20.4% 로 **모든 신호 중 가장 높다.**

> 보통은 약한 신호를 못 재는데, 여기서는 **가장 강해 보이는 신호를 못 잰다.**
> 드물어서다. 데이터를 더 모아서 풀 문제가 아니라 상장사 모집단의 성질이다.

**공정위 기업집단명** — DART 어디에도 없다(실측 확인). 대규모기업집단현황공시 제출
여부로 소속/미소속은 알지만 집단명은 모른다. "계열 경계 초과" 가 손입력 라벨 20개에
묶여 있는 이유다.

**업종의 시점 분리** — 기업개황 API 는 **현재** 표준산업분류만 준다. 2021년 검정에
2026년 업종을 쓰고 있고, 고칠 방법이 없어 한계로 남긴다.

```

   ├─ 층0  이중 출처 신뢰 그래프 — 정형 API(정답) × 본문 추출(예측)
   └─ 층1  구조 분석 — [G1]품질·[G2]경계 게이트가 계산 앞을 막는다
            렌즈 → 가중치 → 투영 두 벌 → 군집(Leiden+CPM) → 층위·중심성
            → 귀무 대조 + 민감도 스윕 → 3상태 판정 → 근거 블록
```

규율을 문서가 아니라 **구조로** 강제한다. `db/asof.py`(시점 조회) ·
`signal/labels.py`(부실 판정) · `screen/inputs.py`(검사 입력) 가 각각 한 곳이다.
손으로 흩어 쓰면 언젠가 어긋나고, 실제로 어긋난 적이 있다.

Python 3.13+ / uv · igraph 1.0(Leiden+CPM) · networkx 3.6(차수보존 셔플) ·
SQLAlchemy 2.x · pytest **402**

Leiden 을 쓰는 이유는 Louvain 이 연결조차 안 된 군집을 만들 수 있어서고
(Traag et al., *Sci Rep* 9:5233, 2019), CPM 을 병행하는 이유는 모듈러리티가 일정 크기
미만 모듈을 원리적으로 못 봐서다(Fortunato & Barthélemy, *PNAS* 104(1), 2007).
실측 CPM 67 vs 모듈러리티 40 — **27개를 놓친다.**

> 패키지명은 `dartweave`. 초기 이름이며 import 경로 전체를 바꿀 이득이 없어 뒀다.

· `collect_industry`(업종) · `collect_events`(주요사항보고) · `collect_delisting`(상장폐지).

## 만들면서 계속 확인한 것

층0은 fixture 107개가 다 통과한 상태에서 실 API 를 붙였고 **결함 11건이 나왔다.
fixture 가 잡은 건 0건이었다** — 파서와 fixture 가 같은 오타를 공유해 자기완결적
허구를 이루고 있었다.

그래서 층1은 설계 전에 탐침을 돌리고, 계획서의 코드가 저장소 코드와 글자 단위로 같은지
기계로 검증한다(`scripts/plan_byte_check.py`). 그런데도 구현 중 결함 4건이 더 나왔고
셋은 **구현자가 계획서 오류를 되돌려 보고**해서 잡혔다.

| 잘못 알던 것 | 재보니 |
|---|---|
| 해소율이 낮다 → 별칭 사전 필요 | 미해소의 91%가 corpCode 에 없는 대상. 분모 문제 |
| 민감도 게이트가 작동한다 | 자기 존재 이유인 사례를 통과시키고 있었다 |
| 공동의존점 경고가 유용하다 | 71.6%에서 뜬다. 소음이었다 |
| CLI 가 수십 초 걸린다 | 1.5초. `uv run` 셋업을 작업으로 오인 |
| `해산`은 부실 신호다 | PFV·SPC 만기 종료. 라벨 오염 |
| 0.06% 보유가 "상호출자" | 규제 용어 오용 + 지분율 누락 |
| 순이익 계정은 `당기순이익` | 실제로는 `당기순이익(손실)`. 0건이 나왔다 |
| 재무 검정도 그래프 안에서 | 요구할 이유가 없었다. 풀자 결론이 바뀌었다 |
