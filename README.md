# red-flags-in-korean-filings

전자공시를 이어서 **개별 공시로는 안 보이는 지배구조 이상 신호**를 찾는다.
상장사 8,974개사 · 지분 관계 12,201건.
점수를 내지 않고, 무엇이 걸렸고 어느 공시에서 나왔는지만 낸다.

**▶ [실행 결과 화면 보기](https://deokjinlog.github.io/red-flags-in-korean-filings/)**
— 실측 수치와 세 가지 발견, 그리고 엔진이 스스로 반려한 판정

---

## 두 가지로 쓴다

**① 질문 → 그래프 검색**

```bash
uv run python scripts/ask.py "태영건설이 흔들리면 어디가 위험해?"
```
```
도달 범위   1홉 122개사 · 2홉 80개사
공동의존점  건설공제조합 1홉 매개3위
순환출자    매우 드묾 — 태영건설 → 삼양사 → 티와이홀딩스 → 태영건설
근거 899자 · 허용 토큰 46개
```

`건설공제조합`은 질문에 없다. 벡터 유사도로는 안 나오고 **구조를 타야** 나온다.
그게 그래프를 쓰는 이유다. 생성은 프롬프트 하나 차이고, 모델은 저 토큰 46개 안에서만
말할 수 있다(벗어나면 `HallucinationDetected`).

**② 종목 검사**

```bash
uv run python scripts/check_company.py --name 케이씨씨
```
```
[순환출자]      매우 드묾 — 상위 1% 밖 (p99=0) · 표본의 99%는 0건 · 최단 5단계
    케이씨씨 → 현대모비스 → 현대자동차 → HD현대 → HD한국조선해양 → 케이씨씨
[계열사 내부거래] 흔함 — 5건 — 상위 5% 이내 아님 (p95=6)
```

**모든 검사가 자기 검증 상태를 달고 나온다.** 걸렸다는 것과 위험하다는 것은 다른
말이고, 우리는 후자를 아직 대부분 모른다. **지분 구조 7종 중 채택된 것은 하나도 없고,
채택된 하나는 재무에서 나왔다.**

| 검사 | 부실과 연관되는가 |
|---|---|
| 결손금 (재무) | **채택** — 14개 조합 전부 유의 · 다중검정 Bonferroni까지 통과 |
| 영업손실 (재무) | **채택(약)** — 14개 조합 전부 유의 · 다중검정은 FDR만 통과 |
| 대기업집단과의 거리 | **채택 안 함** — 통제하면 사라지고, 앞을 보면 기준시점마다 방향이 뒤집힘 |
| 공동의존점 근접 | **반대 방향** — 먼 쪽이 2배(p=0.0007), 감사의견 라벨로도 ×0.50 |
| 순환출자 | 미검정 — 보유 1.7% × 부실 1% = 0.017%, 표본이 구조적으로 부족 |
| 상호 지분 보유 | 미검정 — 신호군 부실 10건으로 최소 20건 미달 |
| 계열 경계 초과 | 미검정 — 공정위 라벨 20개뿐이라 신호군을 못 만듦 |
| 특수관계인 자금거래 | 미검정 |
| 계열사 내부거래 | 미검정 |

```
[공동의존점 근접] 드묾 — 8건 — 상위 1~5% · 2홉 기준
    삼성전자 — 2홉 · 매개중심성 1위
    └ 검정됨 · 부실과 반대 방향 (먼 쪽이 2배 · p=0.0007)
```

## 등급은 실측 분포다

상장사 **8,974개사 · 엣지 12,201** 전수에서 잰다.

| 항목 | 0인 회사 | p95 | p99 | 최대 |
|---|---|---|---|---|
| 순환출자 고리 | **98.3%** | 0 | 1 | 65 |
| 상호 지분 보유 | **96.1%** | 0 | 1 | 4 |
| 2홉 내 공동의존점 | 62.7% | 5 | 8 | 12 |
| 특수관계인 자금거래 | **93.5%** | 2 | 5 | 7 |
| 계열사 내부거래 | **84.5%** | 6 | 18 | 26 |

**기준선은 표본에 민감하다.** 처음엔 대기업 44곳을 씨앗으로 만든 1,490개사에서 쟀는데,
상장사 전체로 넓히니 공동의존점 근접이 71.6% → 37.3% 로 떨어졌다. 옛 표본이 대기업에
치우쳐 허브 근처만 담고 있었던 것이다. 순환출자 최대는 3 → **65** 로 뛰었다.

**종합 점수는 안 만든다.** 합치는 순간 "위험도 0.73"이 되고 아무도 못 믿는다.

| | |

| 차수보존 귀무모형 | 0.7223 (10회) |

절대 기준을 썼다면 0.8535는 "매우 우수"였다. 귀무모형이 이미 0.7223이라는 걸 재보지
않으면 알 수 없다. `채택` · `결론 없음` · `파라미터 의존적` 세 상태는 동등한 반환값이다.

## 시점 규율

```
2023-03 공시   A가 B를 30% 보유   (사실기준일 2022-12, 공시일 2023-03)
2023-08 정정   실은 25%였음        (사실기준일 2022-12, 공시일 2023-08)
```

2023-05에 세상이 알던 값은 **30%** 다. `as_of`만 걸면 25%가 딸려 오고, 그 위에서 한
검정은 무효다. `relation_fact`는 append-only이고 조회는 `db/asof.py` 한 곳에서
`as_of ≤ T AND rcept_dt ≤ T` 를 항상 함께 건다.

## 신호 검정 1호 — 검사 하나가 뒤집혔다

관계 46,821행(상장사 3,983사 × 2021~2024) 위에서 첫 검정을 돌렸다.
특징은 T 이전, 라벨은 T 이후 — `db/asof.py` 가 강제한다.

```
as-of 2022-06-30 · 라벨 창 1,000일 · 순열 3,000회

공동의존점에서 먼 회사   1.9% (76/4038) 부실
가까운 회사              0.9% (28/2958) 부실
                         ×1.99 · p=0.0007
```

**`공동의존점 근접`은 위험 신호가 아니었다.** 오히려 반대 방향이고, 세 시점(2022-06 ·
2023-06 · 2025-12) 모두 같았다. 허브 근처 = 대기업 계열이라는 규모 교란일 가능성이
커서 **인과가 아니라 연관까지만** 말한다. 도구 출력에 그 사실을 붙였다.

**순환출자·상호 지분 보유는 검정 불가.** 그리고 그 판정에 이르는 과정이 이 프로젝트에서
가장 값진 순간이었다.

4개 시점을 기업-연도 패널로 합치니 이렇게 나왔다.

```
circular  supported  4.2% (21/506) vs 1.0% (321/32338)  ×4.18 · p=0.0005
mutual    supported  1.9% (25/1320) vs 1.0% (317/31524) ×1.88 · p=0.0060
```

**부풀려진 값이었다.** 같은 회사가 4개 시점에 각각 들어가 관측이 독립이 아니었다.
회사당 한 번만 세니 순환출자 신호군의 부실이 **10건**뿐 — 우리 자신의 최소 기준
20건에 못 미쳐 `TOO_FEW` 가 됐다.

```
회사 단위 (9,044사 · 부실 134사)
circular  판정 불가 — 신호군 부실 10건
mutual    판정 불가 — 신호군 부실 10건
```

**우리가 만든 가드가 우리 결과를 잡았다.** `--unit` 기본값을 `company` 로 두고,
복제가 유의성을 만드는 현상을 회귀 테스트로 고정했다.

그리고 구조적으로도 부족하다 — 순환출자 보유 1.7% × 부실 발생 1% = 0.017%.
양성 20건에 **10만 기업-연도**가 필요한데 우리는 연 9천이다.

## 신호 검정 2호 — 연속값으로 바꾸니 표본 문제가 풀렸다

순환출자는 보유율 1.7%, 부실은 연 1%. 교집합 0.017% 라 **데이터를 더 모아도 안 된다.**
그래서 모든 회사가 값을 갖는 특징으로 바꿨다 — 차수·매개중심성·도달범위·군집크기.

```
회사 9,044 · 부실 134 · 상위 25% vs 나머지 · 순열 3,000회

degree       ×1.90 · p=0.0003     betweenness   ×2.02 · p=0.0003
out_degree   ×1.62 · p=0.0053     in_degree     ×1.67 · p=0.0030
reach_2hop   ×0.79 (차이 없음)     cluster_size  ×0.76 (차이 없음)
```

겉보기에는 **지분 관계가 많은 회사가 부실이 2배**였다. 상위 10% 로 좁혀도 유지됐다
(degree ×1.87 · out_degree ×2.27). **그런데 아래를 보라.**

그런데 **방향이 갈린다.** 직접 연결(degree)이 많으면 부실이 늘고, 2홉 도달범위와
군집 크기가 크면 오히려 준다. 앞서 공동의존점 근접이 ×0.59 였던 것과 같은 방향이다.
자기가 복잡한 것과 큰 네트워크에 속한 것은 다른 얘기라는 뜻으로 읽힌다.

### 그리고 통제해보니 신호가 사라졌다

의심한 교란은 **탐지 편향**이었다. 부실 라벨은 주요사항보고에서 오는데, 지분 관계가
많은 회사는 공시를 많이 하는 회사이기도 하다. 그러면 부실 공시가 잡힐 확률 자체가 높다.

회사별 총 공시 건수를 재서(3,983사) 4개 층으로 나누고 **같은 층 안에서만** 비교했다.

```
층별 배율 (신호군 ÷ 비신호군)

degree        ×0.16  ×0.18  ×0.53  ×0.49     같은 방향 0/4
betweenness   ×0.16  ×0.16  ×0.95  ×0.59     같은 방향 0/4
out_degree      —    ×1.08  ×0.55  ×0.49     같은 방향 1/4
```

**12개 칸 중 11개에서 방향이 뒤집혔다.** `×1.90 · p=0.0003` 은 전부 공시량이었다.
관계가 많아 보이던 위험은 그냥 공시를 많이 하는 회사였고, 공시량을 맞추면 오히려
부실이 **적다.**

층별로는 양성이 20건 미만이라 각각은 `TOO_FEW` 다. 그래서 "반대 방향이 유의하다" 고도
말하지 않는다. 말할 수 있는 건 하나 — **원래 신호가 통제를 못 견뎠다.**

### 편향 없는 라벨로 다시 재니 같은 답이 나왔다

통제가 맞았는지 확인하려면 **탐지 편향이 없는 라벨**이 필요하다. 감사의견이 그렇다 —
공시를 많이 하든 적게 하든 **모든 상장사가 매년 하나씩 받는다.**

3,983사의 감사의견을 수집했다(한 번 호출에 3개 연도). 표기가 153종이라
정규화가 필요했고, **판정 순서가 결정적이었다** — 의견거절 본문 수천 자에도 "적정" 이
들어 있어서, 적정을 먼저 보면 가장 나쁜 의견이 가장 좋은 의견으로 뒤집힌다.

```
비적정 의견 99사 · 계속기업 불확실성 110사 · 합집합 180사

둘 중 하나 (2,508사 중 148사 = 5.9%)
  degree       4.1% vs 6.5%   ×0.64
  betweenness  3.3% vs 6.8%   ×0.50
  out_degree   3.2% vs 6.8%   ×0.47
```

**통제 없이도 처음부터 반대 방향이다.**

```
① 편향 있는 라벨 · 통제 없음     ×1.90        ← 위험해 보임
② 편향 있는 라벨 · 공시량 통제    ×0.16~0.53   ← 뒤집힘
③ 편향 없는 라벨 · 통제 없음     ×0.47~0.64   ← 뒤집힘
```

②와 ③은 서로 다른 경로인데 같은 답을 냈다. ①이 탐지 편향이었다는 게 두 번 확인됐다.

세 번째 자기반박이다. 층1에서 엔진이 자기 결론을 반려했고, 패널 결과가 복제로 부풀려진
걸 잡았고, 이번엔 유의했던 신호가 교란이었다.

## 신호 검정 3호 — 처음으로 통과한 신호

집단명은 DART 에 없다(list API 에도 `flr_nm` 에도 없음 — 실측). 하지만
**대규모기업집단현황공시를 제출한다는 것 자체가 소속이라는 뜻**이다. 2024년 공정위
공시 전수에서 제출자 **3,397사**를 추출했다.

그리고 **커버리지 편향을 먼저 걸러야 했다.** 그래프에 아예 없는 회사가 오히려 문제가
적어서(2.2% vs 6.6%), 그래프 안팎을 섞으면 결과가 흐려진다. 그래프 안에서만 비교했다.

```
그래프 안 상장사 2,508사 · 감사의견 문제 148사

대기업집단 소속        1.8%  (7/381)
미소속 · 집단과 연결    3.2%  (16/504)
미소속 · 고립          7.7%  (125/1,623)

소속 vs 미소속   ×3.61 · p=0.0002
연결 vs 고립     ×2.43 · p=0.0005
```

**1.8% → 3.2% → 7.7% 단조 증가다.** 대기업집단에 가까울수록 문제가 적고, 가까움의
정도에 따라 단계적으로 다르다. 탐지 편향도 아니다 — 감사의견은 모든 상장사가 받는다.

### 그리고 이것도 채택하지 않았다

가장 그럴듯한 반박 둘이 남아 있었다. **"고립 = 그냥 작은 회사 아니냐"**, 그리고
**"고립 = 그냥 특정 업종 아니냐."** 둘 다 맞는 말이었다.

규모 변수를 잘못 고르면 통제가 왜곡이 된다. 공시 건수로 층을 나눠봤더니 최상위 층에서
고립군이 18.7% 로 튀었다 — 부실한 회사가 공시를 많이 내기 때문이다(유상증자·소송·
관리종목). 층화 변수가 결과변수와 얽히면 안 된다. **자산총계**를 새로 수집했다.

업종도 교란이었다. 표준산업분류로 나눠보니 고립률 41~88% · 문제율 0~11.8% 인데
**둘이 같은 방향으로 움직인다** — 금융은 고립도 문제도 적고, 의료정밀은 둘 다 많다.

```
통제 설정을 흔든다 (2,255사 · 순열 20,000회)

  자산층  업종   셀    배율        p    판정
      1     -     1  ×2.61   0.0000   유의   ← 통제 없음
      4     -     4  ×1.69   0.0193   유의
      2     1    20  ×1.84   0.0050   유의
      2     2   107  ×1.68   0.0152   유의
      3     1    29  ×1.61   0.0279   유의
      3     2   154  ×1.40   0.0978   차이 없음
      4     1    37  ×1.52   0.0500   유의
      4     2   195  ×1.29   0.1571   차이 없음   ← 가장 보수적
```

**통제를 촘촘히 할수록 배율이 계속 줄고 유의성이 사라진다.** 유의해지는 설정을 골라
쓰면 그건 파라미터 고르기다 — 층1에서 모듈러리티 0.85 를 반려한 것과 정확히 같은
이유다. 그래서 **채택하지 않는다.**

방향은 8개 설정 전부에서 일관된다(전부 ×1.29 이상). 크기는 말할 수 없다.

### 앞을 보게 하면 방향도 무너진다

감사의견은 **이미 드러난 문제**다. "사도 되나" 는 드러나기 전을 묻는 질문이라,
기준시점 T 의 구조로 T 이후 730일의 실제 부실(부도·회생·관리절차·영업정지)을
맞히는지 봐야 한다. 엣지는 T 시점에 공시된 것만, 자산은 T 이전 사업연도 값으로
시점을 갈랐다.

```
T=2022-06-30 · 대상 1,757사 · 이후 부실 45사
  소속 1.77%  연결 3.51%  고립 2.45%      통제 없음 ×0.88 → 최보수 ×0.68 (p=0.86)
  유의한 설정 0/7

T=2023-06-30 · 대상 2,055사 · 이후 부실 55사
  소속 1.11%  연결 2.61%  고립 3.14%      통제 없음 ×1.63 → 최보수 ×1.70 (p=0.11)
  유의한 설정 3/7
```

**기준시점 하나 바꿨더니 방향이 뒤집힌다.** 2022년에는 고립이 오히려 안전한 쪽이었다.
크기는커녕 방향도 말할 수 없다.

같은 회사를 두 시점에 걸쳐 합치지 않았다 — 순환출자 검정에서 ×4.18 p=0.0005 가
같은 회사를 네 번 세서 만들어진 적이 있다. 시점마다 따로 내고 일치하는지를 본다.

**그래서 이 도구는 구조로 예측한다고 말하지 않는다.** 걸린 것과 그 근거만 낸다.

## 그러면 잣대가 너무 빡센 건가

구조 신호 7종이 전부 떨어지고 나면 질문이 하나 남는다. **잣대가 너무 빡센 건가,
아니면 구조에 정말 신호가 없는 건가.** 재무 신호를 **같은 틀에** 넣으면 답이 나온다 —
재무는 교과서적으로 부실을 예고한다고 알려져 있으니, 이게 통과하면 잣대는 멀쩡한 것이다.

같은 틀이란: 시점 분리(T 이전 재무 → T 이후 730일 실제 부실), 회사 단위, 자산 규모 ×
업종 교차 통제, 설정 8개를 흔들어 **가장 보수적인 답**을 채택.

```
T=2022-06-30 · 2021년 재무 · 대상 1,892사 · 이후 부실 54사
  결손금            463사   6.05%   통제없음 ×3.32 → 최보수 ×3.70  p=0.0002   채택 7/7
  영업손실          462사   5.19%   통제없음 ×2.48 → 최보수 ×2.13  p=0.0077   채택 7/7
  당기순손실        525사   4.38%   통제없음 ×1.93 → 최보수 ×1.68  p=0.0586   탈락 5/7
  부채비율 200%↑    298사   5.70%   신호군 부실 17건 — 최소 20건 미달로 판정 보류

T=2023-06-30 · 2022년 재무 · 대상 2,075사 · 이후 부실 56사
  결손금            519사   5.20%   통제없음 ×2.79 → 최보수 ×3.15  p=0.0002   채택 7/7
  부채비율 200%↑    301사   6.64%   통제없음 ×3.27 → 최보수 ×3.90  p=0.0004   채택 7/7
  당기순손실        657사   4.57%   통제없음 ×2.49 → 최보수 ×2.59  p=0.0010   채택 7/7
  영업손실          537사   4.28%   통제없음 ×2.00 → 최보수 ×2.03  p=0.0124   채택 7/7
```

**잣대는 멀쩡했다.** 같은 통제, 같은 시점 분리, 같은 보수적 채택 규칙을 재무 신호는
통과한다. 두 기준시점 **모두**에서 통과한 건 **결손금**과 **영업손실** 둘이다.
당기순손실은 시점에 따라 갈렸고(영업외손익이 섞인다), 부채비율은 2022년 기준시점에서
신호군 부실이 20건에 못 미쳐 판정을 보류했다 — 방향은 같다.

| | 검사 | 채택 |
|---|---|---|
| 지분 구조 | 7종 | **0종** |
| 재무 | 5종 | **2종** (결손금 · 영업손실 — 각 14개 조합 전부 유의) |

그래서 도구에 둘을 넣었다. **이 저장소에서 "검정됨 · 채택" 을 달고 나오는 유일한
항목들이다.**

```
[결손금] 2023년 이익잉여금이 마이너스 — 누적 결손 1,333억
    결손 기업의 이후 2년 부실률 실측 5.2~6.1% (전체 2.7~2.9% · 통제 후 ×3.2~3.7)
    └ **채택** · 기준시점 2개 × 통제 설정 7개 = 14개 조합 전부에서 유의

[영업손실] 2023년 영업이익이 마이너스 — 영업손실 575억
    영업손실 기업의 이후 2년 부실률 실측 4.3~5.2% (전체 2.7~2.9% · 통제 후 ×2.0~2.1)
    └ **채택** · 결손금보다 배율은 낮다
```

지분 구조로 부실을 예고하려던 시도는 실패했고, 그 실패는 재무 대조군이 있어야
"우리 방법이 틀렸다" 가 아니라 **"구조에 그 신호가 없다"** 로 말할 수 있다.

### 마지막으로 — 재무를 알고 나서도 구조가 뭔가 보태는가

"단독으로 못 한다" 와 "아무것도 못 한다" 는 다른 말이다. **결손금 여부를 층에 넣고**
구조를 다시 검정했다. 결손 기업끼리, 흑자 기업끼리만 비교하니 재무로 설명되는 부분은
층 안에서 상쇄된다.

```
T=2022-06-30                결손              흑자          통제 후
  고립          6.76% (24/355)   1.31% (11/839)     ×0.89~0.94  전부 차이 없음
  나머지         3.77% (4/106)   2.61% (15/574)

T=2023-06-30                결손              흑자          통제 후
  고립          6.19% (24/388)   1.92% (17/887)     ×1.76~2.19  5개 중 4개 유의
  나머지         2.29% (3/131)   1.67% (11/660)
```

**또 기준시점에서 갈린다.** 2022년에는 구조가 아무것도 안 얹고, 2023년에는 얹는
것처럼 보인다. 재현되지 않으므로 채택하지 않는다 — 흑자 기업 안에서는 방향까지
뒤집힌다(2022년 고립 1.31% vs 나머지 2.61%).

## 많이 쟀으니 보정한다

여기까지 오면서 신호를 수십 번 검정했다. `p<0.05` 를 그대로 쓰면 20번 재서 하나
걸리는 건 우연으로도 일어난다. **여덟 번이나 교란을 잡아낸 저장소가 정작 이걸 안
잡으면 앞뒤가 안 맞는다.**

가족을 어떻게 묶느냐가 결론을 바꾼다. 설정까지 세면 156번인데, 통제 설정 8개는 서로
다른 가설을 8번 검정한 게 아니라 **같은 가설의 민감도 스윕**이고 우리는 이미 그중
가장 보수적인 답만 쓴다. 그래서 세는 단위는 **(신호 × 기준시점) 중 판정이 나온 것**
— 14개다. 표본 미달로 보류한 건 검정을 한 게 아니다.

```
가족 14개 · alpha=0.05 · Bonferroni 임계 p = 0.00357

  결손금 · T=2022            0.0002   Bonf ○  FDR ○   채택
  결손금 · T=2023            0.0002   Bonf ○  FDR ○   채택
  차수(연결 수)                0.0003   Bonf ○  FDR ○   탈락 — 공시량 층화에서 무너짐
  부채비율 200%↑ · T=2023     0.0004   Bonf ○  FDR ○   한 시점뿐
  공동의존점 근접                0.0007   Bonf ○  FDR ○   탈락 — 방향이 반대
  당기순손실 · T=2023          0.0010   Bonf ○  FDR ○   시점 간 갈림
  영업손실 · T=2022           0.0077   Bonf ×  FDR ○   채택(약)
  영업손실 · T=2023           0.0124   Bonf ×  FDR ○   채택(약)
  … 나머지 6건 전부 ×
```

**결손금은 Bonferroni까지 넘고, 영업손실은 FDR만 넘는다.** 그래서 도구가 둘을 같은
강도로 팔지 않는다 — 영업손실은 `채택(약)` 으로 나온다.

그리고 **작은 p 가 곧 채택은 아니다.** 차수(p=0.0003)와 공동의존점 근접(p=0.0007)은
보정을 통과하지만, 하나는 공시량 층화에서 무너졌고 하나는 방향이 반대라 채택하지
않았다. 보정은 '우연히 작은 p' 만 걸러낼 뿐, 방향과 재현은 따로 봐야 한다.

`uv run python scripts/adjust_multiplicity.py`

세 검정이 같은 그림을 그린다 — **관계가 많고 큰 네트워크에 속할수록 문제가 적다.**
"관계가 복잡하면 위험하다" 는 처음 가정과 정반대다.

## 구조

```
DART OpenAPI + 공정거래위원회 공시
   ├─ 층0  이중 출처 신뢰 그래프 — 정형 API(정답) × 본문 추출(예측)
   └─ 층1  구조 분석 — [G1]품질·[G2]경계 게이트가 계산 앞을 막는다
            렌즈 → 가중치 → 투영 두 벌 → 군집(Leiden+CPM) → 층위·중심성
            → 귀무 대조 + 민감도 스윕 → 3상태 판정 → 근거 블록
```

Python 3.13+ / uv · igraph 1.0(Leiden+CPM) · networkx 3.6(차수보존 셔플) ·
SQLAlchemy 2.x · pytest **320**

Leiden을 쓰는 이유는 Louvain이 연결조차 안 된 군집을 만들 수 있어서고
(Traag et al., *Sci Rep* 9:5233, 2019), CPM을 병행하는 이유는 모듈러리티가 일정 크기
미만 모듈을 원리적으로 못 봐서다(Fortunato & Barthélemy, *PNAS* 104(1), 2007).
실측 CPM 67 vs 모듈러리티 40 — **27개를 놓친다.**

> 패키지명은 `dartweave`. 초기 이름이며 import 경로 전체를 바꿀 이득이 없어 뒀다.

## 만들면서 계속 확인한 것

층0은 fixture 107개가 다 통과한 상태에서 실 API를 붙였고 **결함 11건이 나왔다.
fixture가 잡은 건 0건이었다** — 파서와 fixture가 같은 오타를 공유해 자기완결적 허구를
이루고 있었다.

그래서 층1은 설계 전에 탐침을 돌리고, 계획서의 코드가 저장소 코드와 글자 단위로 같은지
기계로 검증한다(`scripts/plan_byte_check.py`, 29/29). 그런데도 구현 중 결함 4건이 더
나왔고 셋은 **구현자가 계획서 오류를 되돌려 보고**해서 잡혔다.

측정이 계획을 뒤집은 것만 여섯 번이다.

| 잘못 알던 것 | 재보니 |
|---|---|
| 해소율이 낮다 → 별칭 사전 필요 | 미해소의 91%가 corpCode에 없는 대상. 분모 문제 (44.5% → 86.1%) |
| 민감도 게이트가 작동한다 | 자기 존재 이유인 사례를 통과시키고 있었다 (비중차 → 배율로 교체) |
| 공동의존점 경고가 유용하다 | 71.6%에서 뜬다. 소음이었다 |
| CLI가 수십 초 걸린다 | 1.5초. `uv run` 셋업을 작업으로 오인 |
| `해산`은 부실 신호다 | PFV·SPC 만기 종료. 라벨 오염 |
| 0.06% 보유가 "상호출자" | 규제 용어 오용 + 지분율 누락 |
