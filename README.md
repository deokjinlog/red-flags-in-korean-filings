# red-flags-in-korean-filings

전자공시(DART)에서 부실 신호를 읽되, **그 신호가 우연과 구분되는지 먼저 검정한다.**
신호가 잡히면 지분 관계 그래프로 누구까지 물리는지 보여준다.

> 실행 예시 화면: [공시가 그리는 기업 경계](https://claude.ai/code/artifact/e9e351cd-c090-4849-8ab8-87812e8bd342)

---

## 왜 만드나

뉴스는 결과를 쓴다 — "태영건설 워크아웃". 공시는 그 앞에 무슨 일이 있었는지를
갖고 있다.

```
2024-02-26   기업어음 발행 부도 · 60억원 · 신한은행 여의도중앙대기업금융센터
   부도사유 : 예금부족
   부도경위 : 기업구조조정촉진법에 의거 채권은행 등의 공동관리절차 개시결정에 따른
             금융채권 상환유예
```

**다 이어야만 나오는 게 따로 있다.** 직접 물린 곳이 119개사라는 건 태영건설의
타법인출자 공시 한 건만 읽어도 나온다 — 그래프가 필요 없다. 그래프가 아니면
못 보는 건 이런 것들이다.

```
케이씨씨 → 현대모비스 → 현대자동차 → HD현대 → HD한국조선해양 → 케이씨씨
```

5단계 순환출자 고리, 차수 15인데 매개중심성 3위인 건설공제조합,
공정위 지정으로는 4개 집단인데 지분으로는 하나인 범현대가.

---

## 지금 나오는 것

실측: 1,490개사 · 지분 엣지 1,892 · 2024 사업연도 · 실행 0.3초.

**공식 지정과 실제 지분 경계가 다르다.** 공정거래위원회 기업집단 지정으로
현대자동차·HD현대·KCC·현대백화점은 서로 다른 집단이다. 지분 관계로는 같은 군집
110개사다. 케이씨씨와 HD한국조선해양은 서로를 소유한다.

**연결은 적은데 끊으면 여러 군집이 갈라지는 곳.** 건설공제조합은 차수 15인데
매개중심성 3위(147,187)다. 여러 건설사가 공동으로 붙어 있는 지점이라, 여기가
흔들리면 서로 무관해 보이던 건설사들이 동시에 영향을 받는다.

**한 회사가 흔들릴 때 직접 물리는 수.** 태영건설 119 · 한화 87 · 에스케이에코플랜트 62.

## 엔진이 결론을 반려한다

위 실행의 판정은 **`parameter_dependent` — 채택하지 않음** 이었다.

| | |
|---|---|
| 모듈러리티 | 0.8535 |
| 차수보존 귀무모형 | 0.7223 (10회 반복) |
| 효과크기 | **+0.1314** — 임계 0.05 통과 |
| 해상도 안정성 | **1.85배** — 임계 1.5배 초과 · **반려** |

절대 기준을 썼다면 0.8535는 "매우 우수"였다. 귀무모형이 이미 0.7223이라는 걸
재보지 않으면 알 수 없다. 그리고 해상도를 0.5→2.0으로 흔들자 가장 큰 군집이
1.85배 변했다 — "가장 큰 군집이 N개사" 류 주장은 이 구간을 못 버틴다.

`결론 채택` · `결론 없음` · `파라미터 의존적` 세 상태는 **동등한 반환값**이다.
`결론 없음`은 예외가 아니다.

## 예측은 아직 못 한다 (표본을 세봤다)

```
2024 1분기 주요사항보고서   1,809건
  표본 1,200건 중 부실 관련    16건
     영업정지 6 · 관리절차 6 · 해산 2 · 회생절차 1 · 부도 1
연간 추정  부실공시 ≈ 96건 · 그중 부도급 ≈ 50건
```

양성 표본이 연 50건인데 특징이 수십 개(재무비율 + 공시 이벤트 + 그래프 위치)면
과적합이 확정적이다. 그래서 모델을 만드는 대신 **신호를 하나씩 검정한다** —
"대주주가 지분을 담보로 넣은 기업은 이후 부실 공시가 유의하게 많은가?" 같은 질문은
표본 50건으로도 답할 수 있다. 특징이 하나니까.

검정된 신호를 쌓아서 예측으로 간다. 검정 없이 모델부터 만들면 아름다운 과적합이 나온다.

## 구조

```
DART OpenAPI
   │
   ├─ 층0  이중 출처 신뢰 그래프
   │       정형 API(정답) × 본문 추출(예측) → 겹치는 구간으로 서로 채점
   │       신뢰 등급 T1·T2·T3 + 충돌 플래그
   │
   └─ 층1  구조 분석 엔진
           [G1] 품질 게이트 ── 법인 해소율 미달 시 실행 거부
           [G2] 경계 게이트 ── 경계 열림 시 층위·중심성 미산출 (군집은 통과)
              ↓
           렌즈 → 가중치 → 투영 두 벌 → 군집(Leiden+CPM) → 층위·중심성
              ↓
           귀무모형 대조 + 민감도 스윕 → 3상태 판정 → 근거 블록
```

**게이트가 계산 앞에 있는 게 핵심이다.** 뒤에 두면 이미 나온 결과를 보고 통과 여부를
정하게 되어 사후 합리화가 들어온다.

## 종목 하나 검사

```bash
uv run python scripts/check_company.py --name 케이씨씨
```

```
케이씨씨 (00105271)
  지분 관계   출자 18곳 · 피출자 1곳 · 공식 집단 KCC
  지분율 조회 34건 · 공정위 공시 N건

  [상호 지분 보유] 서로 보유하는 상대 1곳 (규제상 상호출자와는 별개)
      케이씨씨 ↔ HD한국조선해양 · 최대 3.91%

  [순환출자] 자기 자신으로 돌아오는 고리 1건 (최단 5단계)
      케이씨씨 → 현대모비스 → 현대자동차 → HD현대 → HD한국조선해양 → 케이씨씨
```

점수를 안 낸다. **무엇이 걸렸고 그게 어느 공시·엣지에서 나왔는지**만 낸다.
`--explain` 을 주면 그 근거를 문장으로 옮길 프롬프트와 허용 토큰을 함께 낸다 —
모델 출력이 이 토큰을 벗어나면 `HallucinationDetected` 로 중단된다.

검사 6종: 상호 지분 보유 · 순환출자 · 공동의존점 근접 · 계열 경계 초과 ·
특수관계인 자금거래 · 계열사 내부거래.

**등급은 "좋음/나쁨" 이 아니라 "얼마나 흔치 않은가" 다.** 임의 임계를 쓰지 않고
실측 분포 안의 위치로 말한다.

```
[계열사 내부거래] 드묾 — 13건 — 상위 1~5% (p95=6 · p99=18) · 표본의 84%는 0건
```

기준선 두 벌을 실측해 뒀다.

| | 0인 회사 | p95 | p99 | 최대 |
|---|---|---|---|---|
| 순환출자 고리 | **99.4%** | 0 | 0 | 3 |
| 상호 지분 보유 | **98.5%** | 0 | 1 | 2 |
| 2홉 내 공동의존점 | 28.4% | 6 | 8 | 11 |
| 특수관계인 자금거래 | **93.5%** | 2 | 5 | 7 |
| 계열사 내부거래 | **84.5%** | 6 | 18 | 26 |

그래프 쪽은 1,490개사 전수(`build_graph_baseline.py`), 공정위 공시 쪽은 표본 200사
(`build_baseline.py`). 대부분이 0이라 평균은 쓸모없고 분위수를 본다.

**이 표가 검사 하나를 죽였다.** 공동의존점 근접은 71.6% 가 걸린다 — 등급 없이
"걸림" 만 표시하면 회사 10곳 중 7곳에 경고가 붙고, 그건 정의상 소음이다.
반대로 순환출자는 걸리는 것만으로 상위 0.6% 다.

**종합 점수는 만들지 않는다.** 항목을 하나로 합치는 순간 "위험도 0.73" 이 되고,
그건 아무도 못 믿고 못 반박한다. 항목별로 등급과 근거를 따로 낸다.

**만들자마자 이 도구가 스스로 거짓 경고를 냈다.** 삼양사가 태영건설을 **0.06%**
보유한 걸 "상호출자" 로 경고했다. 캐시한 그래프가 지분율을 버렸고, 규제 용어를
단순 보유에 갖다 붙인 탓이다. 라벨을 정정하고 지분율 임계를 넣어 고쳤으며,
그 0.06% 는 회귀 테스트로 박아뒀다.

## 실행

```bash
uv sync --group dev
cp .env.example .env    # DART_API_KEY 입력

uv run pytest -q                          # 263 passed

# 구조 분석
uv run python scripts/analyze_structure.py \
    --graph graph.json --lens governance --industry 건설

# 미해소 법인 실측 (별칭 사전을 채우기 전에 무엇이 안 풀리는지부터)
uv run python scripts/unresolved_survey.py --sample 200
```

`--graph` 는 `{"edges": [[a, b, type]], "interior": [], "evidence": [...]}` 형태.
`evidence` 를 주면 가중 실행 + 겹2 계수 스윕이 돈다.

종료 코드: `0` 정상 · `2` 인자·파일 · `3` 품질 게이트 · `4` 경계 게이트.

## 이 프로젝트가 계속 배운 것

층0은 fixture 107개가 전부 통과한 상태에서 실 API를 붙였고, **결함 11건이 나왔다.
fixture 가 잡은 건 0건이었다.** 파서와 fixture 가 같은 오타를 공유해 자기완결적
허구를 이루고 있었기 때문이다. 그중 셋은 제품을 깨는 것이었다 —
지분율 분모 상이(보통주 5.01% vs 총발행 4.4%), `계` 소계 행 합산으로 합계가 정확히
두 배, 천주 반올림으로 가짜 충돌 7건.

그래서 층1은 **설계 전에 탐침을 먼저 돌렸고**, 계획서의 코드가 저장소의 코드와
글자 단위로 같은지 기계로 검증한다(`scripts/plan_byte_check.py`, 29/29 일치).
그런데도 구현 중에 결함이 4건 더 나왔고, 그중 셋은 **구현자가 계획서의 오류를
되돌려 보고**해서 잡혔다.

가장 큰 것: `analyze()` 가 경계 열리면 통째로 예외를 던져 유효한 군집 결과까지
버렸다. 실데이터 경계 비율이 48.6%라 **실제로는 아무것도 못 내는 상태**였다.

해소율도 두 번 고쳤다. 처음엔 개인 주주 때문에 29.7%로 찍혔고, 두 번째는 해외
자회사·투자조합 때문이었다 — 미해소 법인의 **91%가 corpCode 에 존재할 수 없는
대상**이었다. 분모에서 빼자 44.5% → 86.1%.

## 기술

Python 3.13+ / uv · httpx · SQLAlchemy 2.x · igraph 1.0 (Leiden + CPM) ·
networkx 3.6 (차수보존 셔플) · pytest

Leiden 을 쓰는 이유는 Louvain 이 연결조차 안 된 군집을 만들 수 있기 때문이고
(Traag et al., *Sci Rep* 9:5233, 2019), CPM 을 병행하는 이유는 모듈러리티 최적화가
일정 크기 미만 모듈을 원리적으로 못 보기 때문이다
(Fortunato & Barthélemy, *PNAS* 104(1), 2007). 실측에서 CPM 67 vs 모듈러리티 40 —
**27개를 놓친다.**

> 파이썬 패키지명은 `dartweave` 다. 초기 이름이며, 저장소명과 다르지만 import 경로
> 전체를 갈아엎을 만한 이득이 없어 그대로 뒀다.

## 한계

- **미래를 예측하지 못한다.** 2024 단일 시점이라 시계열이 없다.
- **인과를 말하지 않는다.** "구조상 병목 위치에 있다"까지가 데이터가 지지하는 범위다.
- **재무를 안 붙였다.** 확산 반경은 개수지 금액이 아니다.
- **공급 관계는 아직이다.** 정형 API에 없어 본문 추출이 필요하고, 재현율·정밀도를
  재야 쓸 수 있다.
