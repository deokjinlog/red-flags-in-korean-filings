<sub>같은 방식을 다른 도메인에 쓴 것 — [`can-this-be-redeveloped`](https://github.com/deokjinlog/can-this-be-redeveloped) (이 재개발 물건 사도 되나 · 판정선을 법령에서 얻는다)</sub>

살 때는 괜찮았습니다. **지금도 그런지**를 묻습니다 — 감사인의 경고도, 자본잠식 진행도,
사채 만기도 전부 산 뒤에 생기는 일이라서요.

## 결론

출발점은 "지분 구조로 부실을 예고한다" 였고, **그건 안 됐다.**

| | 검정한 신호 | 두 시점 전부 채택 |
|---|---:|---:|
| 지분 구조 | 7종 | **0종** |
| 재무·조달·오너·공시행태 | 20종 | **11종** |

안 된다는 걸 **재무 대조군을 같은 잣대에 넣어서** 보였기 때문에, "우리 방법이
틀렸다" 가 아니라 **"구조에 그 신호가 없다"** 로 말할 수 있다.

핵심 다섯은 규모·업종 통제 7설정 × 기준시점 2개 = **14조합 전부**에서 유의하다.

```
                  T=2023   T=2024        해당      부실률
  당기순손실         ×7.94    ×11.12    912~1,027사   5.6~10.8%
  영업손실          ×6.75     ×7.19      763~949사   5.5~11.4%
  결손금            ×5.32     ×8.86      744~759사   7.0~11.7%

  영업현금흐름 음수    ×3.34     ×4.75      764~810사   6.0~ 9.1%
```

**그런데 "이 회사는 망한다" 로 읽으면 안 된다.** 다섯 개가 전부 걸려도 이후 2년
부실률은 5.5~10.2% 다 — **열에 아홉은 아무 일도 없었다.** 그래서 이 도구는 매수·매도를
말하지 않는다. 가격·성장성·수익성은 아예 보지 않으니 **고르는 도구가 아니라 지우는
도구**다.

## 어떻게 검정하는가 — 일곱 개의 규율

이 저장소가 아홉 번 결과를 뒤집은 건 규율을 하나씩 추가하면서다.
전부 **실패에서 나왔다.**

**① 시점 분리.** 특징은 T 이전, 라벨은 T 이후 730일. 엣지는 T 에 공시된 것만,
자산은 T 이전 사업연도 값. `db/asof.py` 가 `as_of` 와 `rcept_dt` 를 **둘 다** 건다 —
하나만 걸면 나중에 정정된 값이 딸려 온다.

**② 회사 단위.** 같은 회사를 여러 기준시점에 걸쳐 합치지 않는다. 순환출자 검정에서
×4.18 p=0.0005 가 **같은 회사를 네 번 세서** 만들어진 적이 있다.

**③ 커버리지.** 그래프에 아예 없는 회사가 오히려 문제가 적다(2.2% vs 6.6%). 구조
검정은 그래프 안에서만 비교한다. 반대로 **재무 검정에는 그래프 소속을 요구하지 않는다** —
요구했다가 DART 타법인출자 API 의 연도별 수록 편차에 표본이 좌우된 적이 있다.

**④ 교란 통제 + 최보수 채택.** 자산총계 × 표준산업분류 교차 층화, 층 안에서만 순열
(`signal/test.py` 의 `stratified_permutation_test`). 층을 쪼개면 검정력이 죽으니 층은
보존한 채 합친다. 그리고 **설정을 8개 흔들어 가장 보수적인 답을 결론으로 삼는다** —
유의해지는 설정을 골라 쓰면 그건 파라미터 고르기다.

**⑤ 다중검정 보정.** 판정이 난 검정 35개를 한 가족으로 묶어 Bonferroni · BH
(`signal/multiplicity.py`). 통제 설정 8개는 서로 다른 가설이 아니라 같은 가설의
민감도 스윕이라 하나로 센다.

**⑥ 관측 창 스윕.** 730 도 우리가 고른 값이라 365·1095 로 흔든다. 창이 수집 끝을
넘으면 `CensoredWindowError` 로 막는다 — 절단은 **조용히** 부실률을 낮춘다.

라벨 자체도 지킨다. `signal/labels.py` 의 `is_distress()` 하나가 무엇을 부실로 셀지
정한다. 해산(PFV·SPC 만기 종료)과 상장폐지 중 합병·스팩청산·이전상장을 세면
**"합병당한 회사" 를 부실로 예측하는 셈**이 되어 라벨이 통째로 오염된다.

## 아홉 번 무너진 기록

그럴듯한 결과가 먼저 나왔고, 한 번 더 확인할 때마다 무너졌다.

| | 이렇게 보였다 | 실제로는 |
|---|---|---|
| 1 | 층1 모듈러리티 0.8535 = 매우 우수 | 귀무모형이 이미 0.7223 · 해상도 1.85배 흔들림 → **반려** |
| 2 | 공동의존점에 가까우면 위험 | **반대 방향** — 먼 쪽이 2배 (p=0.0007) |
| 3 | 순환출자 ×4.18 · p=0.0005 | 같은 회사를 네 번 셈 → 회사 단위로는 표본 미달 |
| 4 | 연결 수 많으면 부실 ×1.90 | **탐지 편향** — 공시 많이 내면 많이 걸린다. 층화하니 붕괴 |
| 5 | 고립이 위험 ×3.61 (감사의견) | 규모·업종 통제하니 ×1.29 로 사라짐 |
| 6 | 규모 통제 후 ×1.69 는 남는다 | 업종까지 통제하니 그것도 사라짐 |
| 7 | 부실 이벤트로 보면 ×1.70 | 기준시점 4개 중 **둘은 방향이 반대** |
| 8 | 당기순손실은 시점에 따라 갈린다 | **내 실수** — 표본을 그래프로 좁혀놔서 얇았다. 풀자 4/4 재현 |
| 9 | 부실 라벨 810건으로 전부 검정 | **답안지에 하나은행(532조)·신한은행·LG전자가 있었다** — 금융당국 제재인 "영업정지" 284건을 부실로 세고 있었다. 빼니 526건(이후 최종부도 폐지 3건을 되찾아 529건) |

몇 개는 더 짚을 값이 있다.

**5·6번 — 고립 신호.** 통제를 촘촘히 할수록 ×1.84 → ×1.29 로 계속 줄고 유의성이
사라졌다. 유의해지는 설정을 골라 쓰면 그건 파라미터 고르기라, 층1 모듈러리티를
반려한 것과 **같은 이유로** 채택하지 않았다.

**7번 — 그래도 죽지는 않았다.** (아래는 답안지 수정 전 측정이다. 새 라벨로 다시
돌리면 T=2021·2022 는 고립군 부실이 11·12건이라 판정 불가, T=2023·2024 는 최보수
설정이 각각 ×1.69 · p=0.14 / p=0.11 로 **여전히 반려**다.) 4시점 배율이
×0.45 → ×0.83 → ×1.46 → ×1.77 로
단조 증가한다. 같은 순서로 그래프 엣지도 4,794 → 15,445 로 느는데, 가장 잘 채워진
T=2024 분류를 모든 시점에 적용해봐도(미래 훔쳐보기라 **진단이지 주장이 아니다**)
×0.81 → ×1.25 → ×1.96 → ×2.34 로 추세가 남는다. 건설·부동산을 빼면 오히려
커진다(×2.34 → ×3.37). 그러니 "구조에 신호가 없다" 보다 **"최근 두 시점에서만
나타나고 왜인지는 이 데이터로 못 가른다"** 가 정확하다.

**절단 — 아홉 번째가 될 뻔했다.** 배율이 시점마다 줄어드는 걸 "시점에 따른 차이" 로
읽을 뻔했는데, T=2023 의 730일 창이 **546일에서 잘려 있었다.** 미래를 훔쳐보는 것의
반대쪽 실수이고, 빠뜨려도 결과가 그럴듯해서 티가 안 난다. 사건을 2026-08 까지
수집해 창을 채우고, 코드가 이걸 막게 만들었다.

**더 재면 대가를 치른다.** 신호를 둘 더 검정하면서 다중검정 가족이 26 → 35 로 커졌고
Bonferroni 임계가 0.00192 → 0.00143 으로 조여졌다. **기존 신호들의 등급이 같이
내려갔다** — 당기순손실은 4/4 에서 3/4 가 됐다. 버그가 아니라 보정의 정의다.

**그런데 지금은 이 등급 자체를 못 쓴다.** 답안지에서 영업정지를 뺀 뒤 신호들이
강해지면서 p 가 대부분 순열 2,000회의 하한(0.0005)에 몰렸고, 가족 35개 중 27개가
Bonferroni 를 통과한다. p 로는 더 이상 신호끼리 등급이 안 갈린다 — 강도 비교는
**배율과 시점 재현**으로 한다.

<details>
<summary><b>규칙을 진화시켜 찾는다 — 실제 결과가 채점한다</b> — 유전 알고리즘으로 조합을 찾되, 채점은 LLM 이 아니라 실제 결과가 한다</summary>

지금까지는 사람이 신호를 하나 생각해내면 우리가 검정했다. 규칙을 **무작위로 만들어
실제 부실 결과로 점수를 매기고, 높은 것만 남겨 섞고 변형**해도 된다. LLM 은 채점에
들어오지 않는다 — "그럴듯한 규칙" 과 "실제로 맞는 규칙" 은 다르고, 필요한 건 뒤쪽이다.

**표본을 가르지 않으면 다중검정이 폭발한다.** 규칙 수천 개를 시도하면 그중 최고점은
거의 확실히 우연이다. 유전 알고리즘의 고전적 함정이고, 이 저장소가 아홉 번 무너진
것과 같은 종류다. 그래서:

```
탐색  T=2021·2022 — 여기서는 몇천 번 시도해도 된다
확정  T=2023·2024 — 탐색 중 한 번도 안 본다. 최종 후보 5개만 여기서 잰다
```

가족은 **최종 후보 개수만큼만** 커진다(5개 × 2시점 = 10건).

### fitness 는 배율이 아니라 신뢰구간 하한이다

3사를 잡아 3사가 다 망하면 배율이 무한대다. 그게 250사를 잡아 34% 맞히는 규칙을
이기면 안 된다. **하한을 쓰면 표본이 작을수록 하한이 저절로 내려간다** — "20건 미만
감점" 같은 걸 붙이면 그 20이 우리가 고른 파라미터가 되지만, 하한은 고를 게 없다.

층화(자산 × 업종)도 fitness 안에 넣었다. 안 넣으면 진화가 **"작은 회사"** 를 찾아낸다
— 작은 회사가 원래 잘 망하니까 그게 제일 높은 점수를 받고, 우리는 규모를 신호라고
부르게 된다. 실제로 고립 신호가 그렇게 무너진 적이 있다.

### 진화가 찾은 것

```
탐색 상위 (fitness = 층화 배율의 95% 하한)
  3.79  결손금 AND 영업현금흐름 음수 AND CB·BW 2회 이상
        OR 발생액 상위 25% AND 영업손실 AND CB·BW 2회 이상

확정 (손 안 댄 표본에서 딱 한 번)
  T=2023  ×3.27 p=0.0005 채택 (198사)
  T=2024  ×4.80 p=0.0005 채택 (215사)
```

**상위 규칙 전부에 "최근 3년 CB·BW 2회 이상" 이 들어 있고, 부채비율은 어디에도
없다.** 아무도 "부채비율 빼라" 고 하지 않았다 — 점수가 실제 결과로 매겨지니까
상관없는 지표가 저절로 떨어져 나간 것이다.

### 시드를 흔들면 이기는 규칙이 바뀐다

층1 결론을 군집 해상도로 흔들어 반려했고, 관측 창도 흔들었다. **유전 알고리즘의
무작위 시드는 정확히 같은 종류의 파라미터다.** 안 흔들면 "우리가 고른 시드에서 나온
규칙" 을 발견이라고 부르게 된다. 시드 10개를 돌렸다.

```
최고 fitness 3.34~3.77 (흔들림 1.13배)  — 점수는 안정적인데 규칙은 매번 다르다

  원자                     승자에 든 횟수
  최근 3년 CB·BW 2회 이상      10/10  ■■■■■■■■■■
  결손금                     7/10  ■■■■■■■
  영업손실                    7/10  ■■■■■■■
  이자보상배율 1 미만            5/10  ■■■■■
  최근 3년 CB·BW 발행          5/10  ■■■■■
  발생액 상위 25%              5/10  ■■■■■
  영업현금흐름 음수               3/10  ■■■
  부채비율 200% 초과            2/10  ■■
  재무CF 연명 · 매출 감소         1/10  ■

  한 번도 못 든 원자: 자본잠식 3종 · 이자보상배율<1 3년 연속
```

**"CB·BW 2회 이상" 은 열 번 중 열 번 살아남았다.** 그래서 이 실험의 결론은 특정
규칙이 아니라 **원자 생존 빈도**다 — 층1 에서 "순위와 존재는 말할 수 있고 크기는
말할 수 없다" 고 한 것과 같은 자리다.

흥미로운 건 **발생액 상위 25%** 가 5/10 로 살아남는다는 점이다. 단독으로는 반려된
신호인데(×1.07, ×1.14) 조합 안에서는 기여한다. 반대로 **자본잠식은 한 번도 못
들었다** — 부실률이 가장 높은데도 해당 기업이 91~108사뿐이라 20건 문턱에서 계속
0점을 받는다.

### 그런데 "진화가 사람을 이겼다" 는 아니다

```
T=2024-06-30 · 부실 91사

  진화 규칙     걸림  215사  정밀도 17.2%  재현율 40.7%
  다섯 다       걸림  317사  정밀도 12.6%  재현율 44.0%
  결손금 단독    걸림  595사  정밀도  9.6%  재현율 62.6%
```

진화는 **더 정밀한 좁은 규칙**을 찾았지 더 강한 신호를 찾은 게 아니다. 정밀도가
9.6% → 17.2% 로 오르는 대신 재현율이 62.6% → 40.7% 로 떨어진다. 부실의 6할을
놓친다. **어느 쪽이 나은지는 데이터가 아니라 쓰는 사람이 정한다** — 놓치는 게
무서우면 결손금 단독이고, 헛걸리는 게 무서우면 진화 규칙이다.

그리고 정밀도 17.2% 도 **걸린 것의 83%는 2년 안에 아무 일도 없었다**는 뜻이다.

`uv run python scripts/evolve_rules.py`

로드맵 E축인데 한 번도 못 쟀던 자리다. DART OpenAPI 에는 없고 거래소에만 있다.
2019~2026 불성실공시 공시 2,896건을 받았는데, **한 표에 여섯 가지가 섞여 있었다.**

| 상태 | 건수 | 신호로 세나 |
|---|---:|---|
| 지정예고 | 1,413 | 아니오 — 아직 예고다 |

'미지정' 과 '거래정지' 가 함정이다. 둘 다 제목에 "지정" 이 들어 있어서 순서를 잘못
두면 280건이 무혐의인데 유죄로 들어가고, 108건이 같은 회사를 두 번 세게 만든다.

**횟수가 곧 용량이다.** 두 기준시점 모두 단조로 오른다:

```
  최근 3년 지정 횟수     T=2023              T=2024
    1회               138사   5.1%       124사   8.9%
    2회                31사  19.4%        37사  24.3%
    3회 이상            10사  40.0%        13사  38.5%
  (전체 기저율)               1.48%              2.36%
```

### 표본 260건이 전량 1,021건을 이기지 못했다 — 규율 하나를 늘린다

벌점을 처음 잰 건 2021~2023 지정 260건 표본이었고, 전량으로 다시 재니 **두 군데가
뒤집혔다.**

| 재본 항목 | 260건 표본 | 전량 1,021건 |
|---|---|---|
| 0~2점 부실률 | 0.0% | 3.2% / 5.2% (기저의 ×2.1) |
| 계단 위치 | 2점 | **8점** (규정선) |
| 대체부과 대비 | 1.6% vs 22.7% (14배) | 5.7~9.1% vs 9.5~15.5% (약 1.7배) |

방향은 셋 다 같고 결론도 같다(복원해 쓰지 말 것). 바뀐 건 크기와 — 더 중요하게 —
**계단의 위치**다. "규정선이 틀렸고 데이터는 2점에서 갈린다" 고 적었는데, 규정선이
맞았다.

왜 틀렸는지는 숫자에 다 있었다. 0~2점 칸이 10사에 부실 0건, 대체부과 칸이 61사에
부실 1건이었다. **1/61 은 한 건만 더 있어도 두 배가 된다** — 비율이 아니라 잡음이다.

그래서 규율을 하나 늘린다 — **칸당 사례가 20건에 미달하면 순서를 말하지 않는다.**
검정 쪽은 이미 이 규칙을 갖고 있었다(신호군 부실 20건 미만 = 판정 불가). 급히 재는
쪽에만 그게 없었고, 그래서 같은 저장소 안에서 두 개의 잣대가 돌아가고 있었다.
`_PENALTY_BANDS` 도 이 규율에 맞춰 20사 미만 구간을 안 낸다.

### 벌점 — 이 도구가 규정을 베끼지 않고 검증하는 자리

처음엔 "횟수로 충분하다" 고 넘겼다. 틀렸다. 지정 1,021건의 공시 본문을 전부 받아
누계벌점을 뽑아 보니 **이진이 등급으로 바뀐다.** 벌점 1점짜리 한 번과 15점은 같은
사건이 아니다.

```
  최근 3년 최대 누계벌점    T=2023              T=2024
    0~4점               90사  2.2% (×1.5)     94사  6.4% (×2.7)
    4~8점               45사  8.9% (×6.0)     36사 13.9% (×5.9)
    8점 이상             44사 25.0% (×16.9)    44사 31.8% (×13.5)
```

**8점은 우리가 고른 값이 아니라 코스닥 공시규정의 관리종목 지정선이다.** 그리고
실측이 그 선과 맞았다 — 두 기준시점 모두 단조이고, 계단이 가장 뚜렷한 곳도 8점이다.
관리종목 칸은 판정선을 거래소가 정해서 우리가 안 정했는데, 여기서는 **우리가 그 선을
검증**할 수 있다. 이 저장소에서 규정과 실측을 맞대볼 수 있는 거의 유일한 자리다.

**시장마다 선이 다르다.** 코스닥 8점 · 유가증권 15점이다. 우리 표본은 코스닥이
71%(725/1,021)라 위 8점 선은 사실상 코스닥 기준이고, 코스닥 안에서 잘 갈린다
(8점 미만 3.7%/12.2% 대 8점 이상 26.3%/31.6%). 유가증권은 8점 이상이 6사뿐이라
못 가른다.

**대체부과 벌점을 복원해서 쓰면 안 된다.** 코스닥은 벌점 대신 제재금을 물릴 수 있고
(231건), 그러면 본문의 부과벌점이 `0.0` 으로 찍힌다. 코아시아씨엠이 그런 경우다 —
기타란에 "부과벌점은 4.0점이며 제재금 1,600만원(4.0점×400만원)을 대체부과함".

처음엔 제재금 ÷ 400만원으로 복원해 쓰려 했는데, 재보니 **거래소가 가볍게 봤다는 것
자체가 정보**였다:

```
  대체부과만 있던 회사      35/44사   5.7% / 9.1%   (×3.9)
  대체부과가 없던 회사     126/110사  9.5% / 15.5%  (×6.5)
  둘 다 있던 회사          18/20사  16.7% / 20.0%
```

복원해서 같은 자에 놓으면 이 회사들이 실제보다 위험한 쪽으로 올라간다. 그래서 신호는
**본문에 적힌 누계벌점 그대로** 쓴다 — 대체부과 회사는 자연히 0점 근처에 모인다
(중앙값 0, 35사 중 27사가 0점). 복원값(`effective`)은 CSV 에만 남기고 신호에 안 쓴다.

**서식이 둘이다.** 코스닥(70758)은 "2. 최근 1년간 불성실공시법인 부과벌점(당해 포함)"
이 누계이고, 유가증권(99802)은 "5. 부과벌점 현황 … 누계벌점" 이다. 한쪽만 보면 절반이
빈다 — 처음 12건에서 누계가 1건만 나왔던 게 그래서다.

**본문 경로는 한 건에 세 번이다.** 접수번호(목록 HTML 의 `openDisclsViewer(...)`) →
뷰어 껍데기에서 문서번호 → `method=searchContents` 로 본문 경로 → 그 경로를 받아
태그를 벗긴다. 1,021건이면 3,063번이라 간격 0.3초·이어받기·연속 실패 10회 정지로 짰다.

**좁은 답안지에서는 검정을 통과하지 못했다** — 해당 44~89사 중 실제 부실이 11~19건이라
최소 20건에 못 미친다. 위 ×13~17 은 통제 전 값이라 배율이라고 부르면 안 된다.

**넓은 답안지(부실+관리종목)에서는 4점 선이 통과했다.** 두 시점 전부 채택 ·
최보수 ×6.60~6.96 · 해당 80~89사에 부실률 31.5~40.0%. 8점 선은 해당 44사로 표본이
얇아 아직 판정 1/2 다. 화면에는 여전히 "같은 구간이었던 N사 중 X%" 라는 관측 형태로
내되, 4점 선이 통제를 견뎠다는 건 별도로 적는다.

**걸린 개수 안에서 다시 벌점으로 쪼개지는 않는다.** 칸마다 20사 미만이 되어 없는
정밀도를 만들게 된다. 개수 안 좁혀주기는 이력 유무(이진)로 하고, 벌점은 전체 구간으로
따로 낸다.

**혼자서는 아무것도 예고하지 않는다.** 이게 이 신호에서 제일 중요한 줄이다:

```
  핵심 5종 밖 + 불성실공시    33사 · 부실  0사   0.00%   ← 두 시점 다 0건
  핵심 5종 안 + 불성실공시   141사 · 부실 25사  17.73%
  핵심 5종 안 + 이력 없음   1142사 · 부실 30사   2.63%
  둘 다 없음              1017사 · 부실  0사   0.00%
```

재무가 멀쩡한 회사의 불성실공시 이력은 부실을 하나도 예고하지 않았다. 그래서 개수에
더하지 않고 감사 층과 같은 **좁혀주는 층**으로 둔다. 이미 걸린 회사 안에서는 크게
가른다 — 5개 걸림 + 이력 있음 67사 29.9% 대 이력 없음 267사 5.2%.

**곁들여 잡은 수집 버그.** KIND 페이지네이션은 끝을 넘기면 빈 응답이 아니라
**마지막 장을 되풀이해서** 준다(2019년 관리종목은 4장이 끝인데 9장을 요청해도 같은
46행이 온다). 마지막 장이 정확히 100행이면 "행 수가 100 미만이면 중단" 이 안 걸려
같은 장을 계속 받는다. 중복 제거가 있어 데이터는 안 틀렸지만, 제거를 빼는 순간
조용히 몇 배로 불어난다. 세 수집기에 "직전 장과 같으면 중단" 을 넣었다.

되는 것만 적으면 다음 사람이 같은 벽에 다시 부딪힌다.

**내부자 매도 (DART elestock)** — 임원·주요주주 소유상황보고에 증감 칸이 있어서
(삼부토건 지배주주 −16,585,879주) 될 것처럼 보였다. 그런데 **`bsns_year` 를 무시한다** —
2019·2021·2023 을 각각 요청해도 같은 4건이 오고 접수일이 전부 2024~2026 이다.
현재 이력 스냅샷이라 과거 시점에 쓰면 2026년 보고를 2021년에 알았다고 세게 된다.
실측으로 T=2024-06-30 이전 접수 보고가 **43,604건 중 0건**이었다.

> 처음엔 "해당 0사" 로 조용히 나왔다. 그게 "그런 회사가 없다" 가 아니라 "애초에
> 시점 분리가 불가능하다" 였다 — 매출채권 0사, 발행 0건과 같은 종류의 신호다.

**회사채 미상환 잔액 (cprndNrdmpBlce)** — 자금 캘린더의 가장 큰 구멍을 메울
것처럼 보였다. 지금은 *발행 공시* 만 갖고 있어서 만기 전에 전환·상환된 사채도 갚을
돈으로 세는데, 이 API 는 회사가 신고한 **미상환 잔액**을 만기 구간별로 준다.

그런데 **이 표에 전환사채를 안 적는 회사가 절반 가까이 된다.** 2023년 말에 확실히
미상환일 CB 를 가진 20사 중 9사가 "-" 로 비어 있었다 — 거짓 음성 **45%**. 같은
회사가 연도에 따라 다르게 적기도 한다(엘앤에프: 2023 "-" → 2024 5,908억).

보정용으로 쓰면 표를 자세히 쓰는 회사만 금액이 줄어 안전해 보이는데, 그건 위험의
차이가 아니라 **공시 습관의 차이**다. 이 저장소가 이미 한 번 걸렸던 탐지 편향과
같은 모양이라 쓰지 않는다. 독립 신호로 세우는 것도 못 한다 — "모름" 이 되는 45%가
무작위가 아니라 공시 습관과 얽혀 있어 남은 표본이 어디로 치우쳤는지 모른다.
(`scripts/collect_bond_balance.py` 에 측정 기록을 남겨뒀다.)

**관리종목 지정 (KRX KIND)** — 상장폐지보다 이른 신호라 라벨로 더 낫다. 그런데
KIND 가 주는 건 **현재 지정된 종목**이지 과거 이력이 아니다(2019~2021년 0건,
2026년 115건). 과거 시점 라벨로 쓰면 **생존편향**이 생긴다.

**자본잠식** — 데이터는 있는데 표본이 구조적으로 부족하다. 완전자본잠식은 18~21사,
부분까지 합쳐도 91~108사다. 그런데 부실률이 9.4~20.4% 로 **모든 신호 중 가장 높다.**

> 보통은 약한 신호를 못 재는데, 여기서는 **가장 강해 보이는 신호를 못 잰다.**
> 드물어서다. 데이터를 더 모아서 풀 문제가 아니라 상장사 모집단의 성질이다.

**공정위 기업집단명** — DART 어디에도 없다(실측 확인). 대규모기업집단현황공시 제출
여부로 소속/미소속은 알지만 집단명은 모른다. "계열 경계 초과" 가 손입력 라벨 20개에
묶여 있는 이유다.

**주석 추출 (우발부채·담보·특수관계자)** — 붙여준 수기 리포트가 가장 값어치 있게
읽은 자리다. 세 겹으로 막힌다:

1. **코드가 없다.** 타법인 출자현황은 셀에 `ACODE` 가 붙어 결정적으로 뽑았는데,
   지급보증 표 34개 중 코드가 붙은 건 1개, 담보 12개 중 0개다. 정형 서식이 아니라
   자유 서술이라 그렇다.
2. **표가 전치되고 다층이다.** 행이 항목, 열이 상대방·권리 종류이고 열 개수가 표마다
   다르다 — 열 위치로는 못 읽는다.
3. **정답지가 없다.** 지급보증 총액을 대조할 정형 데이터가 어디에도 없다. 추출
   품질을 못 재고, 우리 규율은 "재기 전에는 안 쓴다" 다.

그래서 **읽어주지 않고 짚어준다.** 주석은 번호·제목으로 구조화돼 있으니 그 회사의
실제 주석 번호를 뽑아 "17번 담보제공자산, 23번 우발부채와 약정사항, 35번 특수관계자를
보라" 까지 낸다. 7백만 자에서 다섯 곳을 찾아주는 것이 이 단계에서 정직하게 줄 수
있는 값이다.

**업종의 시점 분리** — 기업개황 API 는 **현재** 표준산업분류만 준다. 2021년 검정에
2026년 업종을 쓰고 있고, 고칠 방법이 없어 한계로 남긴다.

## 구조

```
DART OpenAPI + 공정거래위원회 공시 + KRX KIND
   ├─ 층0  이중 출처 신뢰 그래프 — 정형 API(정답) × 본문 추출(예측)
   └─ 층1  구조 분석 — [G1]품질·[G2]경계 게이트가 계산 앞을 막는다
            렌즈 → 가중치 → 투영 두 벌 → 군집(Leiden+CPM) → 층위·중심성
            → 귀무 대조 + 민감도 스윕 → 3상태 판정 → 근거 블록
```

규율을 문서가 아니라 **구조로** 강제한다. `db/asof.py`(시점 조회) ·
`signal/labels.py`(부실 판정) · `screen/inputs.py`(검사 입력) 가 각각 한 곳이다.
손으로 흩어 쓰면 언젠가 어긋나고, 실제로 어긋난 적이 있다.

Python 3.13+ / uv · igraph 1.0(Leiden+CPM) · networkx 3.6(차수보존 셔플) ·
SQLAlchemy 2.x · pytest **402**

Leiden 을 쓰는 이유는 Louvain 이 연결조차 안 된 군집을 만들 수 있어서고
(Traag et al., *Sci Rep* 9:5233, 2019), CPM 을 병행하는 이유는 모듈러리티가 일정 크기
미만 모듈을 원리적으로 못 봐서다(Fortunato & Barthélemy, *PNAS* 104(1), 2007).
실측 CPM 67 vs 모듈러리티 40 — **27개를 놓친다.**

> 패키지명은 `dartweave`. 초기 이름이며 import 경로 전체를 바꿀 이득이 없어 뒀다.

## 만들면서 계속 확인한 것

층0은 fixture 107개가 다 통과한 상태에서 실 API 를 붙였고 **결함 11건이 나왔다.
fixture 가 잡은 건 0건이었다** — 파서와 fixture 가 같은 오타를 공유해 자기완결적
허구를 이루고 있었다.

그래서 층1은 설계 전에 탐침을 돌리고, 계획서의 코드가 저장소 코드와 글자 단위로 같은지
기계로 검증한다(`scripts/plan_byte_check.py`). 그런데도 구현 중 결함 4건이 더 나왔고
셋은 **구현자가 계획서 오류를 되돌려 보고**해서 잡혔다.

| 잘못 알던 것 | 재보니 |
|---|---|
| 해소율이 낮다 → 별칭 사전 필요 | 미해소의 91%가 corpCode 에 없는 대상. 분모 문제 |
| 민감도 게이트가 작동한다 | 자기 존재 이유인 사례를 통과시키고 있었다 |
| 공동의존점 경고가 유용하다 | 71.6%에서 뜬다. 소음이었다 |
| CLI 가 수십 초 걸린다 | 1.5초. `uv run` 셋업을 작업으로 오인 |
| `해산`은 부실 신호다 | PFV·SPC 만기 종료. 라벨 오염 |
| 0.06% 보유가 "상호출자" | 규제 용어 오용 + 지분율 누락 |
| 순이익 계정은 `당기순이익` | 실제로는 `당기순이익(손실)`. 0건이 나왔다 |
| 재무 검정도 그래프 안에서 | 요구할 이유가 없었다. 풀자 결론이 바뀌었다 |

## 한계

- **정밀도가 낮다** — 다섯 개가 전부 걸려도 열에 아홉은 2년 안에 무사했다.
  "이 회사는 위험하다" 를 말할 수 없고 "이 검사에 걸렸다" 까지가 한계다.
- **인과를 못 말한다** — "구조상 병목 위치에 있다" 까지가 데이터가 지지하는 범위다.
- **라벨이 얇다** — 기준시점당 부실 57~91사. 부채비율·자본잠식이 판정 보류로 남은
  이유가 전부 여기다.
- **업종 통제가 시점 분리가 안 된다** — 현재 업종 코드를 과거 시점에 적용한다.
- **본문을 안 읽는다** — 정형 공시만 본다. 특수관계인 거래의 실제 금액은 본문에 있고,
  그걸 뽑으려면 재현율·정밀도부터 재야 한다.
